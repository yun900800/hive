## 二、五种费用类型 × 场景全分析

### 2.1 MEMBERSHIP_FEE — 会员月费（固定收入基本盘）

> 套餐订阅产生的周期性固定收入，是蜂巢的**现金流基石**。

| # | 场景 | 套餐 | 金额 | 业务规则 |
|---|------|------|------|---------|
| 1 | **新会员首月订阅** — 小张注册 FIXED_DESK 套餐 | FIXED_DESK | ¥899 | 按剩余天数比例计费（如 15 号开通只收一半） |
| 2 | **套餐升级** — 小张从 FLEX_DESK(¥499) 升级为 FIXED_DESK(¥899) | FIXED_DESK | 补差价 ¥400 | 立即生效，按剩余天数折算差价 |
| 3 | **套餐降级** — 小张从 FIXED_DESK 降为 VIRTUAL | VIRTUAL | ¥199 | 下月生效，当月保持原套餐 |
| 4 | **企业统一开卡** — 蓝鲸科技开通 5 个 FIXED_DESK | FIXED_DESK ×5 | ¥4,495 | 企业账户统一出账，可随时更换员工名额 |
| 5 | **订阅过期** — 小张忘记续费，套餐到期 | — | ¥0 → 冻结 | 状态 → EXPIRED，闸机通行被拒 |
| 6 | **订阅暂停** — 小张出差 2 周申请暂停 | FIXED_DESK | 按天退款 ¥899×14/30≈¥420 | 暂停期间保留工位，不计费 |
| 7 | **会员升级触发折扣变更** — 小张升到 GOLD 等级 | FIXED_DESK | ¥899 × 0.9 = ¥809 | `MemberUpgraded` 事件 → Billing 重新计算 |

### 2.2 DESK_USAGE — 工位使用费（固定工位增量收入）

> FIXED_DESK 套餐已含工位费，但**临时加购、升级座位、访客日租**会产生额外费用。

| # | 场景 | 会员身份 | 金额 | 业务规则 |
|---|------|---------|------|---------|
| 1 | **套餐内含** — 小张使用自己的固定工位 B-12 | FIXED_DESK | ¥0 | 已含在月费中，不再额外计费 |
| 2 | **临时升舱** — 小张今天想换靠窗工位 A-08 | FIXED_DESK | ¥30/天 | FIXED_DESK 会员享有升舱优惠价 |
| 3 | **访客日租** — 小张的朋友来拜访，需要一个工位办公半天 | 非会员 | ¥80/半天 | 按天计费，无需订阅套餐 |
| 4 | **额外工位** — 蓝鲸科技办公室有 4 个固定座位，今天来了 5 个人 | PRIVATE_OFFICE | ¥50/天 | 超出基础座位数的部分按天加购 |
| 5 | **加时使用** — 小张今天加班到 22:00（工位时段 9:00-18:00） | FIXED_DESK | ¥20/小时 | FIXED_DESK 享有 18:00-22:00 免费，22:00 后按加班费率 |
| 6 | **工位调换** — 小张从 B-12 换到 C-08（同类型平调） | FIXED_DESK | ¥0 | 同类型调换免费，不影响计费 |

#### DESK_USAGE 计费逻辑

```
DESK_USAGE = 
    FIXED_DESK 会员使用自己工位         → ¥0（含在套餐内）
    FIXED_DESK 会员升级座位类型         → 升舱差价 × 使用天数
    非会员 / VIRTUAL 按天租用          → 日租价 × 天数
    PRIVATE_OFFICE 超出基础座位数       → 加座价 × 天数
```

| # | 场景 | 会员身份 | 时长 | 金额 | 业务规则 |
|---|------|---------|------|------|---------|
| 1 | **半天办公** — 小芳（FLEX_DESK）上午 9:00-12:00 在灵活区 | FLEX_DESK | 3h | ¥0 | FLEX_DESK 月费 ¥499 已含每月 40 小时免费额度 |
| 2 | **超出免费额度** — 小芳本月已在灵活区 38h，今天又来 3h | FLEX_DESK | 3h（超 1h） | ¥15 | 超出部分 ¥15/h，封顶不超过月费的 120% |
| 3 | **全天办公** — 小芳在灵活区从早 9:00 待到晚 18:00 | FLEX_DESK | 9h | ¥135 或封顶 ¥100 | 超出额度按小时计，设日封顶避免用户不安 |
| 4 | **VIRTUAL 临时使用** — 老王来蜂巢开个电话会，用灵活区 2h | VIRTUAL | 2h | ¥60 | VIRTUAL 会员无免费额度，按 ¥30/h 计费（高于 FLEX_DESK） |

#### FLEX_USAGE 计费逻辑

```
FLEX_USAGE = 
    FLEX_DESK 会员在免费额度内        → ¥0
    FLEX_DESK 会员超出免费额度         → 超出小时数 × ¥15/h（有日封顶）
    VIRTUAL 会员                      → 实际时长 × ¥30/h
    FIXED_DESK / PRIVATE_OFFICE 会员   → 实际时长 × ¥20/h（他们的套餐不含灵活区）
```

### 2.4 ROOM_USAGE — 会议室使用费（高毛利增值收入）

> 会议室是所有套餐会员都可能使用的**高频增值服务**，按小时计费，毛利极高。

| # | 场景 | 预订时长 | 实际使用 | 金额 | 业务规则 |
|---|-------|---------|---------|------|---------|
| 1 | **准时开始准时结束** — 小张预订 14:00-15:00，15:00 结束 | 1h | 1h | ¥30 | ¥30/h 标准费率 |
| 2 | **提前结束** — 小张 14:00-15:00 的会议室，14:30 就开完了 | 1h | 0.5h | ¥30 | **按预订时长收费**（非按实际），鼓励准时释放 |
| 3 | **超时在 GracePeriod 内** — 小张超时到 15:10 | 1h | 1h10min | ¥30 | 超时 10min ≤ 15min 免罚期，不额外收费 |
| 4 | **超时超出 GracePeriod** — 小张超时到 15:45（原场景） | 1h | 1h45min | ¥30 + ¥40 | 会议室费 ¥30 + 超时费 (45-15)min×¥80/h = ¥40 |
| 5 | **NoShow** — 小张预订了但没人来 | 1h | 0 | ¥30 | 预订开始后 15 分钟未签到 → 自动取消但仍收费 |
| 6 | **企业培训全天预订** — 蓝鲸科技包会议室 9:00-18:00 | 9h | 9h | ¥250 | 全天打包价，低于按小时累加 |
| 7 | **连续超时冲突** — 小张 14:00-15:00 超时到 15:10，影响下一位 15:00 预订者 | 1h | 1h10min | ¥30 + 可能赔款 | 超时占用了下一位的时间，系统自动通知 + 协调 |

#### 会议室超时费的完整计算

```
场景：小张预订 14:00-15:00，实际用到 15:45

预订时长 (bookedSlot)     = 14:00-15:00 → 60min
实际使用 (actualSlot)    = 14:00-15:45 → 105min
超时时长                  = 105 - 60 = 45min
GracePeriod               = 15min（免罚）
计费超时时长              = 45 - 15 = 30min
超时费率                  = ¥80/h（约正常费率 ¥30/h 的 2.7 倍）

费用 = ROOM_USAGE + OVER_TIME_PENALTY
     = (1h × ¥30) + (0.5h × ¥80)
     = ¥30 + ¥40
     = ¥70
```

> **业务逻辑**：超时费率远高于正常费率，不是为赚钱，而是**激励用户准时结束**，释放给下一个预订者。

### 2.5 OVER_TIME_PENALTY — 超时罚金（激励机制 > 收入）

> 超时费的实际目的不是增加收入，而是**防止资源被占用而影响他人**。

| # | 场景 | 超时时长 | 扣除 GracePeriod | 计费时长 | 金额 |
|---|------|---------|-----------------|---------|------|
| 1 | **免罚期内** — 超时 5 分钟 | 5min | 5 - 15 = 0 | 0min | **¥0** |
| 2 | **免罚期内** — 超时 14 分钟 | 14min | 14 - 15 = 0 | 0min | **¥0** |
| 3 | **轻微超时** — 超时 20 分钟 | 20min | 20 - 15 = 5min | 5min（按 1h 算） | **¥80** |
| 4 | **中度超时** — 超时 45 分钟（原场景） | 45min | 45 - 15 = 30min | 30min | **¥40** |
| 5 | **严重超时** — 超时 1.5 小时 | 90min | 90 - 15 = 75min | 75min（按 2h 算） | **¥160** |
| 6 | **极端超时** — 超时 ≥ 2h 且联系不到人 | ≥2h | — | — | **强制结束** + 超时费 + 信用扣分 |

#### 超时费率的业务含义

```
正常费率 ¥30/h  → 鼓励使用，让用户愿意订
超时费率 ¥80/h  → 几乎 3 倍，让用户不敢超时
GracePeriod 15min → 给用户一个"体面的缓冲"，体验友好
```

### 关键发现

| 发现 | 含义 |
|------|------|
| **MEMBERSHIP_FEE 是唯一必收项** | 其他四项都是"按需产生"，只有月费是稳定收入 |
| **FLEX_DESK 计费最复杂** | 有免费额度、超额单价、日封顶三层逻辑 |
| **PRIVATE_OFFICE 客单价最高** | 月费是其他套餐的数倍，但附加费占比最低 |
| **VIRTUAL 的灵活区费率最高** | ¥30/h 是 FLEX_DESK 超额度费率 ¥15/h 的 2 倍，因为没有月费补贴 |
| **超时费对所有套餐一视同仁** | ¥80/h 统一费率，与套餐无关——因为超时占用的资源对所有人都一样 |

## 五、RatePolicy 策略模式 —— 灵活的定价引擎

不同的套餐、不同的会员等级，对应不同的费率。这正是 `RatePolicy` 策略模式的价值：

```
// 费率策略接口
interface RatePolicy {
    Money calculate(UsageRecord usage);
}

// 不同策略实现
FLEX_DESK_RATE       → 灵活区 ¥15/h（超过免费额度后），月封顶 ¥150
FIXED_DESK_RATE      → 灵活区 ¥20/h，无免费额度
VIRTUAL_RATE         → 灵活区 ¥30/h，无免费额度
ROOM_STANDARD_RATE   → 会议室 ¥30/h（基础小会议室）
ROOM_PREMIUM_RATE    → 会议室 ¥60/h（带投影/电视的大会议室）
ROOM_DAY_PACKAGE     → 全天 ¥250（定价低于小时累加）
OVERTIME_RATE        → 超时 ¥80/h（统一费率，跨套餐）
MEMBER_TIER_DISCOUNT → GOLD 9折、PLATINUM 8折（应用于总价）
```

### 定价策略的商业逻辑

```
费率设计原则：
┌──────────────────────────────────────────────┐
│  1. 套餐月费定价 = 覆盖成本 + 合理利润          │
│  2. 灵活区超额费率 FLEX < FIXED < VIRTUAL       │
│     原因：FLEX 已经出了月费，超额是增量          │
│     VIRTUAL 没出月费，按次收费要覆盖成本         │
│  3. 超时费率 ≈ 3× 正常费率                      │
│     目的：不是为赚钱，而是防止超时               │
│  4. 全天打包价 < 小时累加价                      │
│     目的：鼓励长时使用，提高空间利用率            │
│  5. 会员等级折扣 = 粘性激励                      │
│     目的：让用户升等级，锁定长期订阅             │
└──────────────────────────────────────────────┘
```

## 六、从场景反推系统需要的能力

| 业务能力 | 归属 Service | 涉及 Context |
